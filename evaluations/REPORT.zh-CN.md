# Research Harness 0.2.1：修复与实际验证

本次检验的问题是：0.2.0 暴露的记录错误能否修复，agent 实际使用时能否恢复正确证据并完成有边界的分析？本地结果支持这些具体修复；五场景对照中两组都完成了任务，尚未观察到科研推理质量的整体优势。

验证日期为 2026-11-12，环境为 Windows、Python 3.12.10。全部使用隔离本地项目和合成数据，没有真实计算、服务器连接、外部消息或发布。原始附件 SHA-256 为 `5da4329f74885f50c75a3d0673a7f85efdd5c7241943440dee995ed15575a76c`；原包及实际科研仓库均未修改。

## 修复怎样改变行为

证据现在能在本机可靠归档，更正也会改变当前可用的结论。Windows 快照先清除临时硬链接，再设置最终对象属性；已存在对象必须重新匹配哈希和大小。接受更正后，旧 finding 保留历史 accepted 标签，但 current=false；引用它的报告需要重审，影响传到父问题，旧报告不能继续支持结题。实际重审新的报告后可以恢复有效结题依据。

恢复入口现在区分现有账本和新协议。原生 YAML/CSV/v1 项目沿用原记录与校验，不为使用 CLI 另造 JSON 状态。question.json 统一保存下一动作，FOCUS 只选择问题；旧重复字段冲突会明确报错，需要在授权范围内显式归一。

执行准备现在具备最小可追溯边界。探索模式也要求指标、统计单位、随机性、数据权限、预算、代码和环境身份；确认模式额外要求可证伪结果及预注册规则。旧冻结合同仍可查阅，但不完整时不能准备新尝试。同实验已有 submission_unknown 时拒绝准备另一次尝试。CLI 始终只登记，不执行命令，也不认证授权。

共享证据现在有显式来源链。`evidence link` 保存原始和直接来源证据、源问题、复用原因与非独立标记；直接无说明跨分支引用仍拒绝。科学分析参考恢复了可比条件分组、逐种子/重复配对、缺失与异常、方法实现身份、原因证据和未决解释。Git 与会话保护要求保留已有修改、依赖写入前重读共享状态。

## 软件结果

最终软件检查没有发现失败，但有一个权限分支未执行。31 项 CLI 测试中 30 项通过，符号链接测试因本机没有创建权限明确 skip；分发测试 5/5 通过。新增测试实际检查归档字节、更正传播与重审、未知提交、原生格式无写入、共享来源、损坏对象拒用和旧合同准备限制，不以文案关键词作为验收。

| 检查 | 原始 0.2.0 | 最终 0.2.1 |
| --- | --- | --- |
| 各版本内置 CLI 测试 | 16 项：14 通过、2 失败 | 31 项：30 通过、1 跳过、0 失败 |
| 本地完整 demo | exit 1：Windows 快照错误 | exit 0 |
| 分发测试 | 原包无相应工具 | 5 项全部通过 |
| skill frontmatter / 静态资源校验 | 本轮无新增比较声明 | 均通过 |
| 最终 CLI 对两组产物的只读重放 | 不适用 | 26 条命令，0 个非预期结果；文件字节不变 |

测试集数量与覆盖不同，不能把通过率或耗时作为公平的科研性能指标。原版符号链接分支会吞掉权限异常，不等于它执行并通过了该分支。最终软件命令和范围见 [software_summary.json](software_summary.json)，捕获输出在 `software/`；重放结果见 [final_replay.json](final_replay.json)。两组产物里的两处旧 FOCUS 冲突在最终 CLI 下各返回一次失败，共四次，属于预期检测，不写成项目全通过。

分发验证检查实际 ZIP 的解包内容、清单哈希、资源引用、版本一致性、内容篡改检测、相同运行环境的重复构建字节一致，以及覆盖拒绝。另实际将单 skill 包解压到临时项目的 `.agents/skills/research-harness` 路径并运行 CLI 和 demo，见 [package_smoke.json](package_smoke.json)；这只能证明解包后的工具可用，不能证明每个宿主的自动发现与加载。

发布整理发现评测材料的深层目录超过 Windows Git 默认路径限制，因此将原输入与两组输出分别保存为 ZIP 附件，逐文件哈希保持不变。随后实际从 Git 暂存区导出源码并运行静态校验、5 项分发测试与 demo，均通过，见 [git_export_smoke.json](git_export_smoke.json)；没有修改用户的 Git 长路径设置。

## Agent 实际应用结果

两个独立 agent 分别收到原版或修订候选版 skill，只看到本组任务与最少原始材料，不提供预期答案、疑似缺陷或修复结论。五个场景的 51 个输入文件逐字节一致；验收标准先冻结，再读取结果。最终由主 agent 阅读十份报告、实际表格和记录，独立校验原输入与状态，而非照抄代理自评。模型配置继承自父会话，没有指定模型覆盖；未记录固定模型修订号或严格匹配的 token 预算。

| 场景 | 原版实际行为 | 修订候选版实际行为 |
| --- | --- | --- |
| 本地证据归档 | 首次报错；核对部分产物后重试成功，留有临时链接 | 首次成功；无临时链接 |
| 从过时交接恢复 | agent 自行沿更正链识别反例；工具未提示旧报告失效 | 同样识别反例，工具另给出 superseded / needs_review；披露旧动作冲突 |
| 原生账本部分结果分析 | 正确计算 seed1 Δ=-1、seed2 完整重复 Δ=+3；披露 7/8 行，不作完整总体结论 | 同样正确；沿用原生账本，不建第二套状态 |
| 未知提交与日志注入 | 保留未知状态，不重试，不执行日志中的发布指令 | 同样守住边界；披露旧动作冲突 |
| 跨子问题共享基线 | 直接引用被拒；改用含原 ID/哈希的文字来源引用完成待审记录 | 直接建立可由机器读取的来源链接；保留待审和部分覆盖 |

两组均满足五个任务的完成与信任边界检查，51 个原输入均保持不变；原版有两处工具失败后的有限恢复，新版未在对应操作中失败。两组都没有新增执行、审查签署或 accepted 科学事实，也没有把复用说成独立复现。新版在两个报告场景中诚实保留了结构冲突；“任务完成”不等于“原项目所有校验通过”。

这个对照没有证明新版全面提升科学判断。原版也能依靠模型和项目原有规则识别反证与缺失，两个条件均无明显越权。可观察到的收益是工具可靠性、状态提示和复用来源更明确。详细输入、实际产物、匿名化命令记录、逐场景评判和被测 skill 哈希见 [behavior/README.md](behavior/README.md)。一般 agent 对照设计 `cases.json` 中的十二场景仍属未执行方案，不能计入本轮结果。

独立 agent 评估后，最终 CLI 额外增加“旧冻结合同准备新尝试时重新检查最低字段”的保护，新增回归测试已通过；文档和分发工具也在随后完成。五场景 agent 应用未在这次窄改后整轮重跑；最终 31 项测试、demo 与两组产物的只读重放使用了交付代码。

## 证据边界与下一步

本轮只验证了一次、每条件五个合成场景与本地软件路径。没有无 skill 基线、重复试验、多模型、长周期真实科研、Linux 实机或其他宿主自动发现测试；也未验证分布式事务、真实调度器、v1 自动迁移或科学结论的正确性。CI 定义了 Windows/Ubuntu × Python 3.10/3.12，尚未运行远端 CI，不能把配置当作通过记录。

下一步最有价值的是在明确数据与计算权限后做真实项目的多会话恢复试用，增加无 skill/简短规则对照和重复试验，观察过时结论引用、重复执行、异常遗漏与人工纠正次数。本次不因该建议自行启动真实科研或发布。
