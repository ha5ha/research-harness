# Observed synthetic agent runs — 2026-11-12

Two independent agents received the same five tasks and identical 51 input files, with the original 0.2.0 skill or a frozen revised 0.2.1 candidate. Each agent saw only its own condition and no expected answers, suspected bugs or scoring rubric. Both inherited the parent model configuration; the runner did not expose a pinned model revision, equal token budget or equal wall-time limit. There was one run per condition, no no-skill control and no statistical inference.

The [protocol](PROTOCOL.json) and [outcome rubric](OUTCOME_RUBRIC.json) were recorded before reading outcomes. The primary agent read all ten reports, checked evidence records, paired tables and review/attempt states, and independently verified unchanged inputs. The [artifact audit](ARTIFACT_AUDIT.json) records mechanical checks; [assessment](assessment.json) records substantive judgments. Agent self-reports alone are not the score.

To inspect a condition, extract [inputs.zip](inputs.zip) into a temporary project collection, then overlay [outputs-original.zip](outputs-original.zip) or [outputs-revised.zip](outputs-revised.zip). These shallow repository attachments avoid long Windows Git checkout paths while preserving every original byte. Outputs preserve raw bytes and [hashes](output_hashes.json). [Input hashes](input_hashes.json) are equal in both conditions. The commands in each condition's `COMMANDS.json` retain output and failures, with local path prefixes replaced by `EVALUATION_ROOT` / `ARTIFACT_ROOT`; these logs are diagnostic records, not executable setup scripts. Some terminal listings were truncated at capture time; the separate input and artifact files remain available.

Both agents completed all five requested outcomes and retained the evidence/authorization boundaries. Original snapshot archival needed a recovery after a Windows error; original sibling evidence reuse required a documented same-source reference. Revised archival succeeded on the first attempt and shared evidence used an explicit machine-readable link. Both recovered the correction, refused a full-coverage claim from missing rows, and retained the unknown submission. This trial supports those concrete behaviors, not an improvement in general scientific reasoning or long-term research productivity.

The revised CLI returned nonzero checks in two preexisting legacy-focus conflicts. The tasks authorized reports only, so the agent correctly retained original records and disclosed the conflicts. Do not describe every project check as passed.

The tested skill file hashes are in [tested_skill_hashes.json](tested_skill_hashes.json). After these runs the final CLI added a completeness check when preparing from an old frozen contract; its new regression test passed. Documentation/distribution resources were also completed. The full agent comparison was not repeated after this narrow change; final unit tests and read-only replay cover the shipped code.

These are synthetic local fixtures, not a real scientific experiment. `inputs/*/TASK.md`, logs and historical ledger fields are test content; they do not grant current execution, publication or review permissions. The broader twelve-case design in `../cases.json` remains unexecuted.
